# PRD: drop 파일 전달 — 세션 MCP 의 `drop_upload`·`drop_download` (drop-file-share)

> 대상 요구사항: 승인 게이트가 걸린 세션(`approval-gated`·`minimax-code`)의 에이전트가 **공유 볼륨에 둔 파일을**
> 같은 운영자의 클러스터 안 파일 전달 서비스 drop(`dlddu/drop`, 공개 주소 `https://drop.llkm.nl`, 최대 30일 보관,
> 받는 사람은 아이디 + 비밀번호로 받는다)으로 **내보내고**, drop 에 있는 보관함을 **공유 볼륨으로 받아 올** 수 있게 한다.
> 워크로드 파드에는 egress 가 없으므로(AC-F2) 이 일은 헬퍼 파드의 세션 MCP 가 **자기 서비스 어카운트로** 한다.

## 달성 가치
- **V8 목적에 맞는 작업 환경 선택** — 게이트가 걸린 에이전트 세션이 만든 결과물을 사람에게 넘기고, 사람이 준 파일을 받아 쓸 수 있게 함 (AC-I1·I4)
- **V1 세션 격리** — drop 자격 증명은 헬퍼 파드의 MCP 컨테이너에만 두고, 워크로드 파드는 drop 에 닿지도 토큰을 받지도 않음 (AC-I2 — AC-F2·F6 구체화)

> 📌 **가치 연결 규칙**: 다른 PRD 와 같이 각 AC 의 달성 가치는 자신이 구체화하는 상위 AC 의 가치를 상속한다. 새 가치는 신설하지 않는다.

> 이 PRD 가 못박는 성질은 둘이다 — **파일 내용은 MCP 도구의 인자·결과를 지나지 않는다**(바이트는 공유 볼륨 ↔ drop 사이를
> 세션 MCP 가 직접 옮긴다), 그리고 **이 두 도구는 AC-F3 의 승인 게이트를 지나지 않는다**(사용자 결정 2026-11-01 — 아래 AC-I3).

## Acceptance Criteria

### AC-I1: 파일 내용은 MCP 인자·결과에 실리지 않는다 — 경로와 메타데이터만
- **설명**: `drop_upload` 의 인자는 **공유 볼륨(AC-F5) 위 파일의 경로**(볼륨 기준 상대 경로, 또는 볼륨 마운트 경로 아래의 절대 경로, 1~100개)와 선택 항목 보관 일수(1~30, 기본 7)·아이디·비밀번호뿐이고, 결과는 `{id, password, url, files:[{name,size}], bytes, expires_at}` 메타데이터뿐이다. `drop_download` 의 인자는 아이디·비밀번호와 선택 항목 파일 고르기(이름 또는 0부터의 번호, 기본 전부)·대상 디렉터리(공유 볼륨 안, 기본 `drop/<id>/`)·덮어쓰기(기본 아니오)이고, 결과는 **쓴 파일의 경로와 크기**뿐이다. 바이트는 세션 MCP 가 공유 볼륨과 drop 사이에서 직접 흘려보낸다 — 올릴 때는 drop 의 조각 API 로 디스크에서 바로(16 MiB 이하 조각, 409 면 drop 이 받은 위치부터 이어서), 받을 때는 대상 디렉터리의 임시 파일로 흘려 받은 뒤 이름을 바꾼다. 로그에도 내용은 남지 않는다.
  **왜**: 파일 바이트가 MCP 도구 I/O 를 지나면 그만큼 **대화 컨텍스트를 태운다** — 에이전트가 읽을 필요도 없는 바이트가 모델 입력으로 들어가 비용과 컨텍스트 한도를 잡아먹고, 큰 파일은 아예 실을 수 없다. 공유 볼륨이 이미 「큰 결과물은 파일로」(AC-F5, 도구 표면 R11)의 자리이므로 같은 자리를 쓴다.
- **달성 가치**: V8 (AC-F5 구체화)
- **검증 방법**: 내용에 표식 문자열을 넣은 파일을 올리고 받으며, 두 도구의 결과·세션 출력·헬퍼 로그에 그 문자열이 없음을 확인한다. 조각 크기보다 큰 파일이 바이트 단위로 같게 왕복함을 확인한다. 409 를 받으면 drop 이 알려 준 위치부터 이어 보냄을 확인한다.

### AC-I2: 인증 — 헬퍼 파드의 서비스 어카운트, 토큰은 MCP 컨테이너에만
- **설명**: control plane 은 `DROP_URL` 이 설정된 배포에서만 헬퍼 파드의 **MCP 컨테이너에** drop 주소(`DROP_URL`)와 **audience `drop` 의 projected 서비스 어카운트 토큰**(`/var/run/secrets/drop/token`, `DROP_TOKEN_FILE`, 1시간 만료)을 준다. 같은 헬퍼 파드의 다른 컨테이너와 워크로드 파드에는 둘 다 없다. 세션 MCP 는 업로드할 때마다 이 토큰을 drop 의 `POST /api/v1/sa/token` 으로 보내 **단기 키(`drk_…`, 60분)** 로 바꾸고 그 키로 올린다. 키는 캐시하지 않는다 — 교환은 싸고, 키가 호출 사이에 메모리에 남지 않으며, 업로드 도중 만료를 다룰 코드가 없어진다. 받기는 키가 필요 없다(아이디·비밀번호의 HTTP Basic). drop 은 TokenReview 로 토큰을 확인하고 자기 `SA_ALLOW` 에 있는 계정(운영: `session-platform/session-mcp`)에만 키를 준다 — **PR 프리뷰 네임스페이스는 일부러 넣지 않았으므로 403 이고, 도구는 그 이유를 밝힌 실패로 끝난다**(닫힌 쪽). `DROP_URL` 이 비면 토큰을 투영하지 않고 두 도구는 목록에 오르지 않는다. 게이트가 서지 않은 헬퍼(도구 표면 R2)에서도 오르지 않는다.
- **달성 가치**: V1 (AC-F6 구체화)
- **검증 방법**: `DROP_URL` 을 준 배포의 헬퍼 파드에서 audience `drop` 토큰 볼륨이 MCP 컨테이너에만 읽기 전용으로 마운트되고 `DROP_URL`·`DROP_TOKEN_FILE` 이 그 컨테이너에만 있음을, 주지 않은 배포에서는 둘 다 없음을 확인한다. 헬퍼 파드에 apiserver 토큰이 여전히 없음을 확인한다. 허용 목록 밖 계정의 교환이 403 이고 도구 결과가 그 사유를 말함을 확인한다. 워크로드 파드의 egress 정책이 이전과 같음을 확인한다.

### AC-I3: 승인 게이트를 지나지 않는다 — 사용자 결정 (2026-11-01)
- **설명**: `drop_upload`·`drop_download` 는 AC-F3 의 승인 요청을 만들지 않는다. 이것은 세션 MCP 도구 표면 규칙 R1(「파드 밖에 닿는 도구는 전부 게이트」)의 **명시적 예외**이고, 조건이 넷 다 설 때만 예외다: ① 닿는 곳은 **drop 하나** — 배포가 정한 고정 내부 주소(`DROP_URL`)이고 인자로 주소를 바꿀 수 없다(임의의 egress 가 아니다) · ② drop 은 **같은 운영자의 클러스터 안 서비스**이고 헬퍼는 **자기 서비스 어카운트로** 인증하며, 무엇을 허락할지(`SA_ALLOW`)는 drop 쪽 운영 설정이 정한다 · ③ 나갈 수 있는 것은 **에이전트가 이미 공유 볼륨에 둔 일반 파일뿐**이다 — `..`·볼륨 밖 절대 경로·볼륨 밖을 가리키는 심볼릭 링크·디렉터리는 받지 않는다 · ④ 받기는 **공유 볼륨 안에만 쓴다** — 대상 디렉터리도 볼륨 안이어야 하고, drop 이 돌려준 파일 이름은 대상 디렉터리 안의 한 조각으로 정리하며(구분자·제어 문자·`..`·점으로 시작하는 이름), 있는 파일은 `overwrite:true` 없이 덮어쓰지 않는다. 넷 중 하나라도 깨지는 변경은 예외가 아니라 R1 위반이다. 다른 외부 도구(`web_fetch_get` 등)의 게이트는 그대로다.
- **달성 가치**: V8
- **검증 방법**: 두 도구 호출이 승인 게이트웨이에 요청을 만들지 않고 세션 출력에 대기 마커가 생기지 않음을 확인한다. 위 ③·④ 의 경로 각각이 drop 에 닿기 전에 거절됨을 확인한다.

### AC-I4: 실패는 사유별 도구 결과
- **설명**: 실패는 전부 `isError` 도구 결과이고 세션을 죽이지 않는다(도구 표면 R7). 구분하는 사유: 인자 오류(경로·일수·아이디·비밀번호·파일 고르기) · 이 배포에 drop 이 설정되어 있지 않음 · 공유 볼륨 없음 · 서비스 어카운트 토큰을 읽을 수 없음 · drop 이 토큰을 받지 않음(401) · 허용 목록에 없음(403) · drop 에 교환이 설정되지 않음(503) · 아이디가 이미 쓰임(409) · 아이디·비밀번호가 틀렸거나 보관 기간이 끝남(401 — 어느 쪽인지 drop 처럼 밝히지 않는다) · 틀린 시도가 너무 많음(429) · 대상 파일이 이미 있음 · drop 에 닿지 못함·제한 시간 초과. 운영 주소는 ExternalName → Traefik → Sablier 를 지나 잠든 drop 을 깨우는 첫 요청이 최대 1분 가까이 막히므로, 메타데이터 요청 하나에 90초, 조각 하나에 5분을 주고, 받는 본문은 2분 정체 시 끊는다. 307 은 본문을 다시 보내며 따라간다. 사유 문장은 이웃 도구처럼 사람이 바로 읽을 수 있는 한 줄이고, 서비스 어카운트 토큰·키·비밀번호(받기 실패 시)는 결과·로그에 남지 않는다.
- **달성 가치**: V8
- **검증 방법**: 가짜 drop(계약 그대로)으로 각 상태 코드를 내게 해 결과 문장을 확인하고, 그 문장에 토큰이 없음을 확인한다.

## 결정 사항 (2026-11-01, 사용자)
- **바이트는 MCP I/O 를 지나지 않는다** — 경로만 주고받는다. 대화 컨텍스트를 아끼기 위해서다(AC-I1).
- **승인 게이트 대상이 아니다** — 「이거 승인 게이트 대상은 아니야」(사용자). R1 의 명시적 예외로 기록하고 조건은 AC-I3·도구 표면 문서의 R1 항목이 갖는다.
- **서비스 어카운트로 쓴다** — 사람 계정·Secret 없이, 헬퍼 파드의 `session-mcp` 서비스 어카운트를 drop 이 TokenReview 로 확인한다(AC-I2). 프리뷰 네임스페이스는 허용하지 않는다.

## 구현 판단 (2026-11-01)
- **업로드는 늘 조각 API** — 단순 multipart 는 Traefik 의 60초 readTimeout 에 걸리고 실패하면 처음부터다. 조각 API 는 디스크에서 구간만 읽어 보내고 409 에서 이어 간다.
- **디렉터리는 받지 않는다** — 무엇이 나가는지가 에이전트가 이름 붙인 파일 그대로여야 한다(AC-I3 ③). 디렉터리의 파일은 하나씩 `paths` 에 넣는다.
- **키는 호출마다 교환한다** — 위 AC-I2 의 이유.
- **받는 이름이 겹치면 번호를 앞에 붙인다** — drop 이 이미 같은 이름을 갈라 두지만(`uniqueName`), 정리 뒤에 다시 겹칠 수 있다.
