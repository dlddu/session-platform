# PRD: 세션별 플러그인 선택

> 대상 요구사항: 세션을 만들 때 **그 세션에 설치할 마켓플레이스 플러그인**을 이름으로 지정
> (`claude-code-workload.md` AC-E6·`codex-workload.md` AC-J5·`minimax-code-workload.md` AC-G5의 플랫폼 플러그인 위에 얹히는 세션 축)

## 달성 가치
- **V8 목적에 맞는 작업 환경 선택** — 세션마다 그 일에 맞는 플러그인(스킬·명령·MCP)을 골라 받는다 (AC-L1이 AC-E1의 선택 축을 플러그인까지 넓힘)

> 📌 **가치 연결 규칙**: 각 AC는 자신이 구체화하는 상위 AC의 가치를 상속한다. 새 가치는 신설하지 않는다 —
> "어떤 플러그인을 받는가"는 V8의 「어떤 작업 환경을 고르는가」를 타입 안쪽으로 한 단계 더 나눈 것이다.

## 용어
- **플랫폼 마켓플레이스** — `dlddu/plugin-marketplace`(이름 `dlddu-plugins`). 배포가 `plugin-marketplace-url`로 다른 원격을 가리킬 수 있지만 마켓플레이스는 하나다.
- **타입 기본 플러그인** — 세션이 플러그인을 고르지 않았을 때 그 타입이 받는 것: `claude-code`는 `session-platform`(AC-E6), `codex`는 배포의 `CODEX_PLUGINS`(기본 `codex-session`, AC-J5), `minimax-code`는 `mcp-servers`(AC-G5).
- **플러그인 선택** — 생성 요청의 `plugins`: 플랫폼 마켓플레이스의 플러그인 이름 목록(`@마켓플레이스` 접미사 없음).

## Acceptance Criteria

### AC-L1: 생성 시 플러그인 선택 — 타입 기본값을 대체하고, 세션 수명 동안 고정
- **설명**: `POST /sessions`는 선택 필드 `plugins`(문자열 배열)를 받는다.
  - **생략**이면 지금과 같다 — 세션은 타입 기본 플러그인을 받고, 응답·저장 레코드에 `plugins`가 없다.
  - **지정**하면 그 목록이 그 세션이 받는 플러그인의 **전부**다 — 타입 기본값에 더하지 않고 **대체**한다(2026-11-07 사용자 결정). 기본 플러그인도 계속 쓰려면 목록에 함께 적는다. 예: `claude-code`에 `["development"]`만 주면 `session-platform` 플러그인은 설치되지 않는다.
  - 받는 타입은 마켓플레이스 플러그인을 싣는 `claude-code`·`codex`·`minimax-code`다. `shell`과 `approval-gated`(AC-F6 — 외부 자격 증명·플러그인 부트스트랩이 없다)에 목록을 주면 **400**이다. `GET /config`의 `workloadTypes[].takesPlugins`가 이를 알린다.
  - 목록은 1~16개, 중복 없이, 각 이름은 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`다. `null`·빈 배열·배열이 아닌 값·중복·형식 위반은 pod를 만들기 **전에** **400**이다. 이름이 마켓플레이스에 실제로 있는지는 control plane이 보지 않는다(아래 AC-L1 설치 지점).
  - 선택은 모델(AC-E6)처럼 **불변 메타데이터**다 — 세션 레코드에 저장되고, 동결·복원을 건너 유지되며, 복원 pod는 타입 기본값이 아니라 그 세션의 선택으로 뜬다. 기존 세션 경로로 바꿀 수 없다.
  - **설치 지점**은 타입마다 그 타입이 이미 플러그인을 받던 자리 하나다 — `claude-code`는 워크로드 컨테이너의 `CLAUDE_CODE_PLUGINS`(진입점이 각 이름을 `<이름>@dlddu-plugins`로 설치하고, 에이전트가 관리형 설정에서 같은 목록만 켠다), `codex`는 세션 파드 `k3s-mcp-proxy` 사이드카의 시더(`CODEX_PLUGINS` 대신), `minimax-code`는 헬퍼 파드 `k3s-mcp-proxy`의 시더. 선택을 고르지 않은 세션에는 그 변수가 아예 없다.
  - 마켓플레이스에 없는 이름은 그 설치 지점에서 실패한다 — `claude-code`는 진입점이 멈춰 에이전트가 닿지 않으므로 **생성이 실패**하고, `codex`·`minimax-code`는 지금의 마켓플레이스 실패와 똑같이 **플러그인 스킬 없이** 세션이 뜬다(K3s MCP는 그대로).
- **달성 가치**: V8
- **구체화 대상**: AC-E1(·G1·J1)의 타입 선택 — 같은 선택 축을 타입 안의 플러그인까지 넓힌 것. AC-E6·AC-J5·AC-G5의 「플랫폼이 정한 플러그인」은 이제 **타입 기본값**이다.
- **검증 방법**: 세 타입 각각에 목록을 주어 만든 세션의 응답·레코드에 그 목록이 있고 해당 설치 지점 컨테이너에만 그 목록이 실리며, 생략한 세션에는 실리지 않음을 확인한다. 동결 뒤 복원한 세션이 같은 목록을 유지하고 복원 pod에도 실림을 확인한다. 위의 잘못된 요청이 모두 400이고 pod가 생기지 않음을 확인한다.

## 결정 사항 (2026-11-07, 사용자)
- **지정은 타입 기본값을 대체한다** — 추가가 아니다. 「정확히 이 플러그인들」이 세션 수명 내내 읽기 쉽고, 기본 플러그인을 빼고 싶은 경우도 같은 필드 하나로 표현된다.
- **이번 범위는 API(control plane·data plane)와 K3s MCP `session_create`다.** 운영자 SPA의 새 세션 화면은 바꾸지 않는다 — 화면에서 만든 세션은 지금처럼 타입 기본값을 받는다.

## 알려 둘 경계
- 플러그인은 모두 **같은 플랫폼 마켓플레이스**에서 온다. 세션이 임의의 마켓플레이스·git 원격을 지정하는 길은 없다 — 마켓플레이스 토큰(K3s MCP가 `plugin-marketplace` 레포로 좁혀 발급)의 범위를 넓히지 않기 위해서다.
- 테넌트(AC-K3)는 타입만 제한하고 플러그인은 제한하지 않는다. 테넌트별 허용 플러그인이 필요해지면 후속 결정이다.
- `claude-code`의 플러그인 새로고침은 없다(AC-J7은 `codex` 전용). `codex`의 새로고침은 그 세션의 선택을 다시 받는다.
