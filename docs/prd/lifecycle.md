# PRD: 세션 라이프사이클 & 워크로드별 스냅샷

> 대상 요구사항: ~~② CRIU 기술 기반~~ (2026-11-01 퇴역), ③ 세션 maximum idle 60분 이후 스냅샷, 파드 종료 시 자동 아카이브(2026-11-15, AC-B5)
>
> 📌 **요구사항 ② 퇴역 (2026-11-01)**: CRIU는 모든 워크로드에서 퇴역했고 동결·복원은 **파일시스템 아카이브** 하나로 통일됐다(`../criu-verification.md` 상단 배너). 요구사항 ②는 기록으로만 남기며, 이 PRD의 AC는 그것에 기대지 않는다.
>
> 📌 **범위 (2026-08-08 개정, 2026-09-03 갱신, 2026-11-01 개정)**: 아래 AC-B1~B3의 **동결·복원 메커니즘은 모든 워크로드 타입이 같다** — 에이전트가 세션의 상태 디렉터리와 누적 출력(scrollback)을 파일시스템 아카이브로 내보내고, control plane이 generation 펜스 트랜잭션(prepare → committing → 회수, 실패 시 abort)으로 외부 스토리지에 중계한다. 타입별로 다른 것은 **아카이브에 무엇이 담기는가**(보존 대상)와 **어느 게이트 뒤에 있는가**뿐이다: `shell`은 홈 디렉터리 파일 + scrollback(AC-D4, `SHELL_ARCHIVE_ENABLED`), `claude-code`·`minimax-code`는 작업 디렉터리·HOME·대화 기록 + scrollback(AC-E5·AC-G4, 각자의 게이트), 게이트를 쓰는 타입(`minimax-code`)은 거기에 세션 공유 볼륨 내용이 더해진다(AC-F5, 그 타입의 게이트). 게이트가 꺼진 타입은 동결할 수 없다 — 리퍼는 세션을 live로 두고 명시적 snapshot은 service unavailable로 거부된다. 유휴 한계·상태 전이·pod 회수 등 **타이밍과 관측 가능한 계약은 모든 타입이 동일**하다. *(이전 판은 `shell`을 CRIU 체크포인트로 두고 「아래 CRIU 서술은 `shell` 타입 기준」이라 적었다.)* 게이트를 쓰는 타입은 회수·복원 대상에 헬퍼 보조 파드(AC-F4)와 공유 볼륨(AC-F5)이 더해지고, 승인 대기 구간에서 유휴 기준이 구체화된다(AC-F3 — [`approval-gate.md`](./approval-gate.md)).

## 달성 가치
- **V2 유휴 자원 회수** — 유휴 세션을 동결하여 pod 자원 회수
- **V3 끊김 없는 세션 연속성** — 워크로드별 체크포인트/복원으로 상태 보존

## Acceptance Criteria

### AC-B1: 60분 유휴 후 스냅샷
- **설명**: 세션의 유휴 시간(마지막 read/write 이후 경과 시간)이 60분에 도달하면, 시스템은 세션 pod의 체크포인트(스냅샷)를 타입별 메커니즘으로 생성하고 세션 상태를 `snapshot`으로 전이한 뒤 pod를 회수한다. 60분은 **최대 유휴 한계**이다.
- **달성 가치**: V2, V3
- **구체화**: "마지막 read/write" = 마지막 클라이언트 workload I/O로 확정한다. `shell`은 쉘 read/write(AC-D5), `claude-code`는 state-branched output read와 prompt write(AC-E2/E3)다. 게이트를 쓰는 타입(`minimax-code`)도 같은 기준을 쓰되, **승인 대기가 진행되는 동안에는 클라이언트 I/O가 없어도 `lastAccess`를 갱신해 유휴 카운트를 멈춘다**(AC-F3 — 게이트 타입에서만 성립하는 의도적 예외). passive SSE 연결·output/reset event·comment keepalive는 상태를 바꾸거나 `lastAccess`를 touch하지 않으며 활동이 아니다. 단, reset 뒤 전체 replay를 위한 `POST /read`는 일반 workload read이므로 활동으로 세고 idle을 승격할 수 있다. 동결 메커니즘: 모든 타입이 파일시스템 아카이브다 — `shell`=홈 디렉터리 파일 + scrollback(AC-D4) / `claude-code`=작업 디렉터리·HOME·대화 기록 + scrollback(AC-E5, `claude-code-workload.md`) / `approval-gated`=그것에 공유 볼륨 내용(AC-F5)을 더하고 헬퍼 보조 파드를 동반 회수(AC-F4, `approval-gated-workload.md`). `shell`은 체크포인트가 진행되는 동안 쉘 프로세스 트리를 일시정지(SIGSTOP)하고 write를 거부하며, 스냅샷이 중단되면 재개(SIGCONT)한다
- **검증 방법**: 세션을 60분간 미사용으로 두면 스냅샷이 생성되고 상태가 `snapshot`으로 바뀌며 pod가 회수됨을 확인한다. 경계값(예: 59분)에서는 동결되지 않으며 output 없는 SSE keepalive만으로 동결이 영구 차단되지 않음을 확인한다. snapshot으로 stream이 끊긴 뒤 SPA가 자동 read/stream으로 즉시 복원하지 않고 Restore 화면으로 이동하는지도 확인한다.

### AC-B2: 스냅샷 복원
- **설명**: `snapshot` 상태의 세션에 접근(read/write/전환)하면, 시스템은 새 pod에 체크포인트를 복원하고 세션을 `active`로 전이한다. 복원은 모든 타입이 아카이브 전개다(복원 대상 pod에는 `session-platform.dev/restore-archive` 주석이 붙는다) — `shell`은 홈 디렉터리를 전개하고 scrollback을 preload한 뒤 그 홈에서 **새 쉘**을 기동하고(AC-D4), `claude-code`는 작업 디렉터리·HOME을 전개하며(AC-E5), 게이트를 쓰는 타입은 거기에 더해 새 헬퍼 보조 파드와 그 라운드의 새 공유 볼륨을 세우고 아카이브의 공유 볼륨 내용을 그 볼륨에 전개한다(AC-F4/F5).
- **달성 가치**: V3
- **검증 방법**: `snapshot` 세션 접근 시 복원이 수행되어 `active`로 전이되고 응답 가능 상태가 됨을 확인한다.

### AC-B3: 스냅샷·복원 무결성
- **설명**: 스냅샷 생성 직전의 세션 상태가 복원 후에도 보존된다. 체크포인트/복원 과정에서 세션 데이터 손실이 발생하지 않는다.
- **달성 가치**: V3
- **구체화**: 보존 대상 상태의 정체는 타입별로 다르지만 **모두 온디스크 상태 + 누적 출력**이다 — `shell`은 홈 디렉터리 파일과 누적 출력 버퍼 → AC-D4 (`shell-workload.md`, *2026-11-01 개정*: 환경 변수·cwd·쉘 변수·실행 중인 프로세스·열린 FD는 **보존되지 않는다**, 복원 쉘은 새 쉘), `claude-code`는 대화 기록·작업 디렉터리·누적 출력 버퍼 → AC-E5 (`claude-code-workload.md`), 게이트를 쓰는 타입은 거기에 **세션 전용 공유 볼륨의 내용**이 더해진다 → AC-F5 (`approval-gate.md`). 모든 경우 "복원 후 보존 대상 위에서 이어짐 + 커서 유효"라는 관측 계약은 같다.
- **검증 방법**: `shell`은 동결 전 홈 디렉터리 파일·scrollback cursor를(그리고 환경 변수·cwd가 **이어지지 않음**을), `claude-code`는 대화 기록·작업 디렉터리·bounded output과 cursor를, 게이트를 쓰는 타입은 거기에 더해 공유 볼륨의 파일을 마커로 세팅 → 타입별 스냅샷 → 복원 후 동일 상태가 유지되는지 확인한다.

### AC-B4: 삭제된 세션 복원
- **설명**: 동결이 커밋될 때마다 control plane은 아카이브와 같은 외부 스토리지에 그 세션의 **매니페스트**(세션 id·이름·워크로드 타입·모델·플러그인·추론 수준·소속 테넌트·생성 시각과 방금 커밋한 아카이브 참조)를 세션 id 하나에 하나씩 덮어써 남긴다. 세션 레코드(ConfigMap)는 삭제(AC-A3)나 pod 유실 정리(AC-C5)와 함께 사라지지만 아카이브와 매니페스트는 남으므로, 세션 id를 아는 호출자는 `POST /sessions/{id}/recover`로 그 세션을 **같은 id로** 되살릴 수 있다. 복원은 매니페스트로 `snapshot` 상태의 레코드를 다시 세운 뒤 AC-B2와 같은 경로로 새 pod에 마지막 아카이브를 전개하고 `active`로 돌려준다. 되살아나는 것은 **마지막으로 동결된 시점의 상태**다 — 그 뒤(삭제 직전까지 `active`였던 구간)의 작업은 아카이브에 없으므로 돌아오지 않는다. 같은 id의 세션이 아직 있으면 **409**, 매니페스트가 없는 id(한 번도 동결이 커밋되지 않았거나, 이 기능이 생기기 전에 사라진 세션)는 **404**다. 매니페스트를 쓰지 못한 동결은 아카이브 실패와 똑같이 롤백된다 — 커밋된 동결은 언제나 복원할 수 있다.
- **달성 가치**: V3
- **구체화**: 호출자 범위는 AC-K2를 따른다 — 테넌트 호출자는 **매니페스트의 소속이 자기 테넌트인** 세션만 복원할 수 있고, 다른 테넌트·무소속 세션의 id는 없는 id와 똑같이 404로 답한다. 복원은 pod를 세우므로 AC-K3처럼 소속 테넌트가 **지금도** 그 워크로드 타입을 허용받아야 한다(아니면 403). 운영자는 모든 세션을 복원한다. 그 타입의 아카이브 게이트가 꺼져 있거나 외부 스토리지가 없는 배포는 503이며 아무것도 쓰지 않는다. 레코드를 다시 세운 뒤 복원이 실패하면(예: 로그인 슬롯 소진) 세션은 `snapshot`으로 남고 다음 접근이 AC-B2대로 복원을 다시 시도한다. 매니페스트 이전에 사라진 세션의 아카이브는 메타데이터가 없어 복원 대상이 아니다(2026-11-12 사용자 결정).
- **검증 방법**: 동결 → 삭제한 세션이 복원 호출로 같은 id·이름·타입·소속으로 `active`가 되고 새 pod 위에서 동결 전 누적 출력이 이어짐을 확인한다. 살아 있는 id는 409, 매니페스트가 없는 id·다른 테넌트의 id는 404, 허용이 좁혀진 타입은 403이며 거부된 호출 뒤에 레코드·pod가 생기지 않음을 확인한다.
- **자동 아카이브와의 관계** (*2026-11-15, AC-B5*): 자동 아카이브가 켜진 배포에서는 `active`·`idle` 세션을 지울 때도 control plane이 파드를 지우기 **전에** 매니페스트를 쓴다 — 마지막 동결 아카이브 참조는 그대로 두고, 지워질 파드가 올릴 자동 아카이브의 참조(`autoArchive`)를 더한다. 복원은 그 자동 아카이브가 실제로 올라와 있으면 그것을, 없으면 마지막 동결 아카이브를 전개한다. 그래서 한 번도 동결되지 않은 세션도 파드가 자동 아카이브를 올렸으면 복원할 수 있고, 둘 다 없는 id만 404다. 동결과 자동 아카이브가 같은 키를 쓰므로(AC-B5) 둘 중 무엇이 남았는지는 객체의 `writer`로 가린다 — 지워진 파드가 쓴 것이면 자동 아카이브로, 아니면 마지막 동결로 기록해 복원한다. 위의 「되살아나는 것은 마지막으로 동결된 시점의 상태」는 자동 아카이브가 없을 때의 결과다.

### AC-B5: 파드 종료 시 자동 아카이브 (*2026-11-15 신설, 사용자 결정*)
- **설명**: 아카이브 게이트가 켜진 모든 워크로드 타입에서, 워크로드 파드가 지워질 때 — 스팟 회수·노드 비우기의 eviction, control plane 밖에서의 삭제, 사용자의 세션 삭제(AC-A3) — 파드는 종료 직전에 자기 세션 상태를 AC-B3과 같은 아카이브로 묶어 외부 스토리지에 **직접** 올린다(자동 아카이브). control plane이 내려가 있어도 동작해야 하므로 업로드는 control plane을 거치지 않는다.
  - **아카이브 키** (*2026-11-15 개정, 사용자 결정*): 세션의 아카이브는 키 하나(`sessions/<세션 id>/checkpoint.tar`)다. AC-B1의 동결과 자동 아카이브가 **모두 이 키에 덮어쓴다** — 세션마다 객체가 하나라 쌓이지 않는다. 객체에는 누가 썼는지가 메타데이터(`writer`)로 붙는다: 동결은 `generation:<세대>`, 자동 아카이브는 `pod:<파드 이름>`. 세션 레코드·매니페스트의 체크포인트도 같은 `writer`를 기록한다. 이 개정 전에 동결된 세션은 기록된 옛 키(`<파드>/<세대>/checkpoint.tar`)에서 그대로 복원되고, 다음 동결부터 이 키를 쓴다.
  - **덮어쓰인 아카이브**: 키가 하나라, 드물게 기록과 다른 쓰기가 키에 남을 수 있다(동결 도중 control plane이 바뀌어 늦게 도착한 업로드, URL을 거두지 못한 파드의 업로드). 복원은 객체의 `writer`가 기록과 다르면 **경고를 남기고 그 아카이브로 복원한다** — 같은 세션의 아카이브이므로 거부하지 않는다(사용자 결정). 그 대신 조금 이르거나 늦은 상태일 수 있다.
  - **업로드 URL**: control plane은 파드마다 세션의 아카이브 키에만, 그리고 그 파드를 `writer`로 붙여서만 쓸 수 있는 서명 URL을 **2시간** 유효하게 발급해 파드의 에이전트에 넣고(서명이 `writer` 헤더를 덮어 파드가 다른 이름으로 쓸 수 없다), 유휴 리퍼의 주기 스캔마다 남은 시간이 **1시간 이하**면 새 URL로 바꿔 넣는다(유효한 URL도 10분마다 다시 넣어, 컨테이너가 재시작돼 잃은 URL을 되찾게 한다). 파드는 생성 때 받은 그 키의 주소와 다른 URL은 받지 않는다. control plane 장애 동안에도 파드는 마지막으로 받은 URL이 만료될 때까지(최소 약 1시간, 최대 2시간) 아카이브할 수 있다.
  - **종료 직전 동작**: 파드의 종료 유예는 110초이고, 아카이브와 업로드는 100초 안에 끝나야 한다. 에이전트 타입은 진행 중인 턴을 기다리지 않고 **멈추며**(그 턴의 end 마커는 `status=canceled`), 아직 시작하지 않은 대기 프롬프트는 버리고 그 수를 세션 출력에 사실로 남긴다. `shell`은 프로세스 트리를 정지시키고 홈 디렉터리와 누적 출력을 묶는다. 이후 파드는 입력을 받지 않는다.
  - **올리지 않는 경우**: URL이 없거나 만료된 파드(아직 URL을 받지 않은 생성·복원 중인 파드, 복원 전 대상 파드), 그리고 control plane이 동결을 확정한 뒤 회수하는 파드 — control plane이 회수 직전에 URL을 거둬 같은 상태를 두 번 올리지 않는다.
  - **게이트 타입**: 워크로드 파드의 egress가 헬퍼 파드뿐인 타입(`minimax-code`)은 헬퍼 파드의 세션 MCP 컨테이너가 업로드를 중계한다. 헬퍼는 같은 키의 주소로만 중계하고, 중계가 시작될 것이면 끝날 때까지 자기 종료를 미룬다(시작 알림이 15초 안에 없으면 미루지 않는다).
  - **채택**: control plane은 파드를 잃은 세션(AC-C5)을 만나면 — read·write가 실패했을 때와 유휴 리퍼의 주기 스캔에서 — 세션의 아카이브 키가 **그 파드가 쓴 것**(`writer`가 그 파드)인지 본다. 키에 이전 동결이 남아 있으면(파드의 업로드가 닿지 않음) 채택하지 않는다. 그 파드가 쓴 것이면 세션을 지우는 대신 그 아카이브를 체크포인트로 삼아 `snapshot`으로 전이하고 매니페스트를 쓴다. 이어지는 접근은 AC-B2 경로로 새 파드에 복원되고, 실패한 read·write는 그 복원 뒤의 결과로 답한다. 없으면 AC-C5대로 정리한다.
- **달성 가치**: V3
- **구체화**: AC-B3의 아카이브 형식과 AC-B2의 복원 경로를 그대로 쓴다 — 자동 아카이브는 「누가 언제 올리는가」만 다르다. 파드는 자기 세션의 아카이브 키에 쓸 수 있으므로 자기 세션의 동결 아카이브를 덮을 수 있다 — 세션 안의 사용자 코드가 자기 세션의 상태를 바꾸는 것과 같은 범위다. 게이트는 배포 설정 `AUTO_ARCHIVE_ENABLED`이고, 켜지면 아카이브 게이트가 켜진 타입 전부에 적용된다.
- **못 막는 것**: 종료 통보 없이 노드가 사라지는 경우(커널 패닉, 스팟 회수 통보를 놓친 경우), 100초 안에 묶고 올릴 수 없는 크기, URL 만료보다 긴 control plane 장애, 진행 중이던 턴의 결과. 이때는 마지막 동결 아카이브(AC-B4)까지만 남는다.
- **검증 방법**: 파드를 control plane 밖에서 지운 세션이 read 한 번으로 새 파드 위에서 `active`가 되고 지우기 전 누적 출력·파일이 이어짐을, 업로드가 없으면 404임을 확인한다. 동결 확정 회수 파드가 올리지 않음, URL이 1시간 이하로 남으면 바뀜, 다른 주소의 URL을 받지 않음, 진행 중 턴이 멈추고 대기 프롬프트가 버려짐, 게이트 타입의 중계와 헬퍼의 종료 지연, 삭제한 세션이 자동 아카이브로 복원됨을 확인한다.
