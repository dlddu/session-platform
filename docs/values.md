## 제품 가치

### V1: 세션 격리
- **유형**: 구체적
- **설명**: 모든 세션은 전용 data plane pod에서 독립적으로 실행되어, 한 세션의 장애·부하·보안 이슈가 다른 세션으로 전파되지 않는다. (1 세션 = 1 pod)

### V2: 유휴 자원 회수
- **유형**: 구체적
- **설명**: 최대 60분 이상 사용되지 않은 세션은 스냅샷으로 동결하고 pod 자원을 회수하여, 활성 세션에만 컴퓨팅 자원을 집중한다. 동결 **메커니즘은 워크로드 타입에 따라 다르다** — `shell`은 CRIU 체크포인트(V6/AC-D4), `claude-code`는 작업 디렉터리·대화 기록·출력 버퍼의 파일시스템 아카이브(V7/AC-E5). 회수되는 자원과 관측되는 상태 전이는 타입과 무관하게 동일하다.

### V3: 끊김 없는 세션 연속성
- **유형**: 추상적
- **설명**: 스냅샷으로 동결된 세션도 다시 접근하면 동결 직전 상태 그대로 재개된다. 사용자는 세션이 멈췄다는 사실을 거의 인지하지 못한 채 작업을 이어간다. 복원 **메커니즘과 "보존되는 상태"의 정체는 워크로드 타입에 따라 다르다** — `shell`은 CRIU로 되살린 쉘 프로세스 트리(메모리 상태, AC-D4), `claude-code`는 아카이브에서 복원한 대화 기록·작업 디렉터리(디스크 상태, AC-E5). 사용자가 보는 연속성(이전 문맥 위에서 이어짐, 커서 유효성)은 타입과 무관하게 동일하다.

### V4: 자유로운 멀티세션 전환
- **유형**: 추상적
- **설명**: 사용자는 보유한 여러 세션 사이를 제약 없이 오갈 수 있으며, 전환 대상 세션의 상태(active/idle/snapshot)와 무관하게 일관된 경험으로 접근한다.

### V5: 일관된 세션 상태
- **유형**: 구체적
- **설명**: 세션 상태 전이와 동시 접근은 ConfigMap(resourceVersion CAS) + Lease 기반 atomic operation으로 처리되어, 경쟁 상황에서도 세션 상태가 깨지거나 중복 처리되지 않는다.

### V6: 인터랙티브 쉘 세션 (기본 워크로드 타입)
- **유형**: 구체적
- **설명**: 하나의 세션은 전용 data plane pod 안에서 지속 실행되는 **인터랙티브 쉘**(기본 `/bin/bash`, PTY에 연결)이다. 사용자는 write API로 쉘의 stdin(입력: 명령/키 입력)에 쓰고, read API로 쉘의 stdout/stderr(출력)를 읽는다. 쉘의 프로세스 트리 — 환경 변수, 현재 작업 디렉터리, 쉘 변수·함수·alias, 실행 중인 포그라운드 자식 프로세스, 열린 파일 디스크립터 — 가 곧 세션의 "상태"이며, 이 상태가 idle·snapshot·restore를 거쳐도 동결 직전 그대로 이어진다.
- **비고**: V6는 **"세션이 무엇인가"**를 정의하는 기반 가치이고, V1~V5는 세션을 격리(V1)·회수(V2)·복원(V3)·전환(V4)·일관 처리(V5)하기 위한 품질 속성이다. **2026-08-08 개정**: V6는 이제 유일한 워크로드가 아니라 **기본 타입**(`workloadType=shell`, 미지정 시 기본값)이다. 위 서술(PTY·프로세스 트리·CRIU 대상)은 `shell` 타입에만 적용되며, 두 번째 타입은 V7이다. V1~V5는 두 타입 모두에 적용된다.

### V7: 에이전트 세션 — 클로드 코드 CLI
- **유형**: 구체적
- **설명**: 세션 워크로드로 **클로드 코드 CLI**를 선택할 수 있다(`workloadType=claude-code`). 이 타입에서 write는 프롬프트가 되어 pod 안에서 `claude --model <세션 model> -p <프롬프트>` 1회 실행을 트리거하고, read는 그 실행 출력을 커서 기반으로 회수한다. 각 실행은 원샷(print 모드)이지만 pod에 남는 대화 기록과 작업 디렉터리를 이어받으므로, 연속된 write는 하나의 이어지는 대화가 된다. 자격 증명(`ANTHROPIC_BASE_URL`·`ANTHROPIC_AUTH_TOKEN`)은 플랫폼 Secret에서 주입되고, 모델은 세션별로 지정한다. 구체 명세는 `prd/claude-code-workload.md`(AC-E1~E6).
- **비고**: V7은 V6와 **대등한 워크로드 타입**이지 상위/하위 관계가 아니다. 사용자가 보는 세션 API(생성·read/write·전환·상태)는 두 타입이 동일하며, 다른 것은 pod 안에서 무엇이 도는가와 무엇을 보존하는가뿐이다. 특히 V7은 상주 프로세스가 없어 **CRIU를 필요로 하지 않는다** — V2·V3를 파일시스템 아카이브로 달성한다(AC-E5).
