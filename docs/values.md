## 제품 가치

### V1: 세션 격리
- **유형**: 구체적
- **설명**: 모든 세션은 전용 data plane pod에서 독립적으로 실행되어, 한 세션의 장애·부하·보안 이슈가 다른 세션으로 전파되지 않는다. (1 세션 = 1 pod)

### V2: 유휴 자원 회수
- **유형**: 구체적
- **설명**: 최대 60분 이상 사용되지 않은 세션은 스냅샷으로 동결하고 pod 자원을 회수하여, 활성 세션에만 컴퓨팅 자원을 집중한다. 동결 **메커니즘은 워크로드 타입에 따라 다르다** — `shell`은 CRIU 체크포인트(AC-D4), `claude-code`는 작업 디렉터리·대화 기록·출력 버퍼의 파일시스템 아카이브(AC-E5). 회수되는 자원과 관측되는 상태 전이는 타입과 무관하게 동일하다.

### V3: 끊김 없는 세션 연속성
- **유형**: 추상적
- **설명**: 스냅샷으로 동결된 세션도 다시 접근하면 동결 직전 상태 그대로 재개된다. 사용자는 세션이 멈췄다는 사실을 거의 인지하지 못한 채 작업을 이어간다. 복원 **메커니즘과 "보존되는 상태"의 정체는 워크로드 타입에 따라 다르다** — `shell`은 CRIU로 되살린 쉘 프로세스 트리(메모리 상태, AC-D4), `claude-code`는 아카이브에서 복원한 대화 기록·작업 디렉터리(디스크 상태, AC-E5). 사용자가 보는 연속성(이전 문맥 위에서 이어짐, 커서 유효성)은 타입과 무관하게 동일하다.

### V4: 자유로운 멀티세션 전환
- **유형**: 추상적
- **설명**: 사용자는 보유한 여러 세션 사이를 제약 없이 오갈 수 있으며, 전환 대상 세션의 상태(active/idle/snapshot)와 무관하게 일관된 경험으로 접근한다.

### V5: 일관된 세션 상태
- **유형**: 구체적
- **설명**: 세션 상태 전이와 동시 접근은 ConfigMap(resourceVersion CAS) + Lease 기반 atomic operation으로 처리되어, 경쟁 상황에서도 세션 상태가 깨지거나 중복 처리되지 않는다.

### V8: 목적에 맞는 작업 환경 선택
- **유형**: 추상적
- **설명**: 사용자는 세션을 만들 때 자신의 목적에 맞는 **작업 환경(워크로드)을 선택**할 수 있다. 플랫폼이 제공하는 격리·회수·복원·전환·일관성(V1~V5)은 어떤 환경을 골랐든 동일하게 적용되므로, 사용자는 환경을 바꾸려고 다른 도구나 다른 플랫폼으로 옮겨갈 필요가 없다.
- **비고**: 이 가치가 담는 것은 **선택 가능하다는 사실과 그 선택이 플랫폼 보장을 훼손하지 않는다는 점**뿐이다. 어떤 환경을 제공하는지(현재 인터랙티브 쉘, 클로드 코드 CLI)와 각 환경이 어떻게 동작하는지는 **수단**이므로 PRD에서 정의한다 — 삭제된 V6·V7은 바로 그 수단을 가치 자리에 올려서 문제였다. 새 워크로드 타입이 늘어나도 이 가치는 그대로 유지된다.
