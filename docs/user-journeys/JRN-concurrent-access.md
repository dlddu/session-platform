> 다른 여정의 화면에서 이미 드러난다.

## 2. 여정 정의

**대상 사용자 (페르소나)**
P1 멀티세션 작업자 + P2 자동화 클라이언트 ([README](./README.md#페르소나)).
한 세션을 사람과 프로그램이 함께 쓰거나, 사람이 브라우저 탭 두 개로 같은 세션을 여는 상황이다.

**진입 맥락**
세션 하나에 접근 경로가 둘 이상 존재한다 — 열어둔 탭 두 개, 또는 작업자와 야간 배치.

**트리거**
두 요청이 우연히 겹친다. 아무도 의도하지 않았고 아무도 조율하지 않았다.

**사용자 목표**
"동시에 건드리면 안 된다"는 규칙을 스스로 지키지 않아도 되는 것. 조율은 플랫폼의 몫이라고 믿는 것.

**완료 기준**
겹친 요청들이 끝난 뒤 **모든 클라이언트가 같은 하나의 세션 상태를 본다** —
pod가 둘 생기지도, 스냅샷이 두 번 찍히지도, 한쪽 입력이 사라지지도 않는다.

## 3. 단계별 상세

> 단계 식별자는 순번이 아닌 슬러그다. 순서가 바뀌어도 식별자는 유지한다.
> P2는 감정이 없으므로 P2 주도 단계에서는 "생각·감정" 자리에 **호출자가 관측하는 결과**를 적는다.

### `STP-parallel-clients` 한 세션에 둘 이상이 붙는다

- **사용자 행동**: 작업자가 노트북과 데스크톱에서 같은 세션을 열어둔다. 또는 자동화가 그 세션에 주기적으로 read/write를 보낸다.
  아무도 "지금 내가 쓰는 중"이라고 선언하지 않는다.
- **터치포인트**: 워크스페이스 화면(여러 탭) · read/write API (호출자 관점)
- **생각·감정**: (P1) "다른 데서도 열어놨는데 괜찮나?" / (P2 관측) 요청이 정상 수락된다.
- **페인포인트 / 이탈 위험**: 동시 사용이 위험하다고 느끼면 사람이 스스로 락을 만들어 쓰기 시작한다
  → 동시 접근을 정상 사용으로 다루고, 문서·UI 어디에도 "한 번에 하나만"이라는 규칙을 두지 않는다.
- **관련 AC**: AC-C2, AC-C3

### `STP-collision` 요청이 겹친다

- **사용자 행동**: 없다 — 겹침은 관측되지 않는다.
  같은 세션에 복원·동결·read·write가 동시에 도달하고, 시스템이 상태 전이를 하나만 성공시킨다.
- **터치포인트**: 없음 (의도적 비시각화)
- **생각·감정**: (P1) 아무 일도 일어나지 않은 것처럼 느낀다 — 이것이 성공이다.
  / (P2 관측) 전이를 놓친 요청은 실패가 아니라 이미 진행된 결과를 따르거나, 재시도 가능한 충돌(409)로 명확히 응답된다.
- **페인포인트 / 이탈 위험**: 충돌이 애매한 500으로 새어 나오면 자동화가 무한 재시도에 빠진다
  → 재시도 가능한 충돌과 진짜 오류를 상태 코드로 구분하고, 같은 요청의 재시도가 부작용을 두 번 만들지 않게 한다.
- **관련 AC**: AC-C1

### `STP-consistent-result` 모두가 같은 상태를 본다

- **사용자 행동**: 작업자가 두 번째 탭을 새로고침하고, 자동화가 다음 요청을 보낸다. 둘 다 같은 세션 상태를 본다.
- **터치포인트**: 워크스페이스 상태 배지·콘솔 · 세션 조회 응답
- **생각·감정**: (P1) "양쪽이 다르게 보이지 않네." / (P2 관측) 조회 결과가 유효한 단일 상태로 수렴한다.
- **페인포인트 / 이탈 위험**: 탭마다 다른 상태가 보이면 사용자는 어느 쪽을 믿을지 몰라 세션을 버린다
  → 상태의 출처를 하나로 유지하고, 화면은 자기가 마지막에 본 상태가 아니라 서버 상태를 따른다.
- **관련 AC**: AC-C1, AC-C3

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 복원과 동결이 동시에 요청됨 | 하나만 성공하고 나머지는 그 결과를 따른다 | `STP-consistent-result` |
| 진행 중인 전이와 충돌 | 재시도 가능한 충돌(409)로 응답. 자동화는 백오프 후 재시도 | `STP-collision` |
| 전이 도중 담당 인스턴스 장애 | 다른 인스턴스가 이어받아 마무리하고, 중간 상태를 남기지 않는다 | `STP-consistent-result` |
| 삭제와 복원이 동시에 발생 | 같은 잠금 아래에서 처리되어 복원 대상이 되살아나지 않는다 | `JRN-session-deletion`의 `STP-delete-settled` |
| 화면이 오래된 상태를 들고 있음 | 서버 응답으로 교체하고 필요한 경우 다시 조회 | `STP-consistent-result` |
