# 테스트 문서: drop 파일 전달 — 세션 MCP 의 `drop_upload`·`drop_download`

## 검증 대상 AC
- AC-I1: 파일 내용은 MCP 인자·결과에 실리지 않는다 — 경로와 메타데이터만 (PRD: drop 파일 전달)
- AC-I2: 인증 — 헬퍼 파드의 서비스 어카운트, 토큰은 MCP 컨테이너에만 (PRD: drop 파일 전달)
- AC-I3: 승인 게이트를 지나지 않는다 — 사용자 결정 (2026-11-01) (PRD: drop 파일 전달)
- AC-I4: 실패는 사유별 도구 결과 (PRD: drop 파일 전달)

## 테스트 시나리오

### 시나리오 1: 공유 볼륨 → drop → 공유 볼륨 왕복, 게이트 없이
- **사전 조건**: `DROP_URL` 이 실물 drop 을 가리키고 그 drop 의 `SA_ALLOW` 에 이 네임스페이스의 `session-mcp` 가 있는 배포. 공유 볼륨이 켜진 게이트 타입(`minimax-code`) 세션 1개
- **실행 단계**: (a) 워크로드 파드에서 표식 문자열을 담은 파일을 공유 볼륨에 쓴다 → (b) 에이전트가 그 경로로 `drop_upload`(아이디·비밀번호 지정)를 부르게 한다 → (c) drop 의 받기 API(아이디·비밀번호, `Accept: application/json`)로 목록과 파일을 직접 받는다 → (d) 에이전트가 같은 아이디·비밀번호로 `drop_download`(대상 `in`)를 부르게 한다 → (e) 워크로드 파드에서 받은 파일을 읽는다 → (f) 세션 출력을 훑는다
- **기대 결과**: (c) 목록에 파일 하나가 원래 이름·크기로 있고 내용이 표식 문자열이다. (e) 공유 볼륨의 `in/` 아래 같은 내용의 파일이 있다. (f) 승인 대기 마커가 없다(AC-I3). 두 도구의 결과에는 경로·메타데이터만 있다(AC-I1)
- **검증 AC**: AC-I1, AC-I2, AC-I3

### 시나리오 2: 경로 경계와 실패 사유
- **사전 조건**: 계약대로 답하는 가짜 drop(서비스 어카운트 교환·조각 업로드·받기, 상태 코드를 고를 수 있음)과 임시 공유 볼륨
- **실행 단계**: (a) `..`·볼륨 밖 절대 경로·볼륨 밖을 가리키는 심볼릭 링크(파일·디렉터리)·디렉터리·없는 파일로 `drop_upload` → (b) 볼륨 밖 `dest`·볼륨 밖을 가리키는 심볼릭 링크 디렉터리·파일인 `dest` 로 `drop_download` → (c) drop 이 `../../x`·`/etc/passwd`·`..`·`.hidden`·빈 이름·겹치는 이름을 돌려주게 하고 받기 → (d) 이미 있는 파일로 받기, 그다음 `overwrite:true` 로 받기, 대상이 볼륨 밖을 가리키는 링크인 경우 `overwrite:true` → (e) 교환 403·업로드 409(아이디 겹침)·받기 401·429 → (f) 조각 업로드 중 409(drop 이 더 앞선 위치를 받았다고 답함)와 307 → (g) `DROP_URL` 없는 배포·게이트 없는 배포의 도구 목록
- **기대 결과**: (a)·(b) 전부 drop 에 닿기 전에 거절되고 교환이 일어나지 않는다. (c) 모든 파일이 대상 디렉터리 바로 아래에 점으로 시작하지 않는 서로 다른 이름으로 쓰이고 볼륨 밖에 아무것도 생기지 않는다. (d) 처음에는 아무것도 쓰지 않고 거절, 두 번째는 덮어쓴다. 링크 너머 파일은 그대로다. (e) 각 사유가 한 줄로 구분되고 토큰이 결과에 없다. (f) drop 이 말한 위치부터 이어 보내 원본과 같은 바이트가 쌓이고, 307 은 본문을 다시 보내 따라간다. (g) drop 도구가 목록에 없다
- **검증 AC**: AC-I1, AC-I3, AC-I4

### 시나리오 3: 운영 주소 — 잠든 drop 깨우기
- **사전 조건**: 운영 배포(`DROP_URL=http://drop-external.drop.svc.cluster.local`), drop 이 Sablier 로 0 으로 내려가 있는 상태. 공유 볼륨이 켜진 게이트 타입(`minimax-code`) 세션 1개. PR 프리뷰 배포 1개
- **실행 단계**: (a) 운영 세션에서 수십 MiB 파일 하나로 `drop_upload` → (b) 공개 주소 `https://drop.llkm.nl/get` 에서 결과의 아이디·비밀번호로 받는다 → (c) 프리뷰 세션에서 `drop_upload`
- **기대 결과**: (a) 첫 요청이 깨우기를 기다린 뒤 성공하고 결과의 `url` 이 공개 주소다. (b) 같은 파일을 받는다. (c) 403 — 허용 목록에 없다는 사유로 실패한다
- **검증 AC**: AC-I2, AC-I4
