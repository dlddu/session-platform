# 주석 정책 — 필요 사유를 댈 수 없는 주석은 남기지 않는다

> 이 문서는 `dlddu/session-platform`의 **주석 판정 기준(SSOT)** 이다. 어떤 주석을 남기고 어떤
> 주석을 지울지에 대한 판단은 개별 리뷰의 취향이 아니라 이 문서를 근거로 한다.
> 판정을 뒤집고 싶으면 **개별 주석이 아니라 이 문서를 먼저 고친다.**

## 왜 이 정책이 있나

주석은 아무도 검증하지 않는다. 코드·문서·테스트는 CI가 붙잡지만, 주석이 코드와 어긋나도
빌드는 초록이다. 그래서 **필요한 이유를 말하지 못하는 주석**은 값이 없는 데서 그치지 않는다 —
원본만 고쳐질 때 조용히 거짓이 되어, 다음 사람을 틀린 방향으로 이끈다.

정합 상태 = 판정 대상 범위의 주석 중 **필요 사유를 댈 수 없는 것이 없음.**

## 판단 기준

### 필요성 시험

**「이 주석을 지우면, 이 코드를 고치러 온 사람이 틀린 판단을 하거나 그 판단에 필요한 사실을
확인하는 데 상당한 비용을 치르는가?」**

예라면 **그 결과**를 적은 한 문장이 필요 사유다 — 무엇을 틀리게 되는가, 무엇을 어디서 다시
찾아야 하는가. **사유를 한 문장으로 댈 수 없으면 지운다.** 애매함은 보존의 근거가 아니다.
지운 주석은 git 이력에 남는다.

### 유지 대상 (이 밖은 제거)

1. **기계가 읽는 주석** — 정책 대상이 아니며 지문·판정 **모두**에서 제외한다:
   `//go:` · `nolint` · `eslint-` · `@ts-` · `prettier-ignore` · `istanbul ignore` · `c8 ignore` ·
   `# noqa` · `# type:` · `# pragma` · `# pylint:` · `# fmt:` · `shellcheck` · `# syntax=` ·
   `yaml-language-server:` · `검증 AC:` · `검증 시나리오:` · `mock-exception:` · `mockup:`
   (각각 Go 툴체인 · 린터 · `scripts/e2e/check-ac-mapping.sh` · `scripts/e2e/check-scenario-mapping.sh` ·
   `scripts/check-render-fidelity.py` · `scripts/check-fidelity-allowlist.py`가 파싱한다.
   지우면 게이트가 깨진다.)
2. **doc 주석** — exported Go 식별자는 Go 관례대로 **식별자 이름으로 시작하는 1줄** doc 주석과
   패키지 주석을 유지한다. 다만 **그 1줄이 시그니처를 그대로 옮겨 적기만 하면**
   (`CreateRequest is the input to Manager.Create.`) 관례를 채우는 것이 아니라 선언을
   되풀이하는 것이므로 제거 후보다. TS/TSX에는 doc 주석 의무가 없다.
3. **필요 사유가 있는 주석** — 이 레포에서 흔한 사유(예시이지 면제가 아니다 — 이 종류라도 주석마다
   사유를 댄다): CRIU·커널·컨테이너 런타임 제약, **온클러스터에서 관측한 사실**
   (날짜·환경이 붙은 것), 동시성·락·순서 계약, 코드 형태만으로는 보이지 않는 함정,
   외부 시스템(k8s API·CRIU·Claude Code)의 문서화되지 않은 동작.

### 판정 규칙

- **사유는 결과를 말한다.** 「중요함」·「참고용」·「나중에 필요할 수 있음」은 사유가 아니다.
- **불필요의 흔한 유형**: 코드 재진술, 저장소 문서 재진술, PR·커밋 이력 재진술, 작업 흔적
  (누가·언제·끝난 TODO·경위), 장식·구분선, 소감·추측, 주석 처리된 코드. 목록은 시험을 대신하지
  않는다 — 목록에 없어도 사유를 못 대면 지우고, 목록의 모양이어도 사유가 서면 남긴다.
- **더 나은 자리가 있으면 옮긴다.** 필요한 지식이라도 이름·타입·테스트·저장소 문서로 옮겨
  코드가 스스로 말하게 할 수 있으면 옮기고 주석은 지운다. 옮기는 변경은 같은 PR에 둔다.
- **틀린 주석**은 사유가 있으면 고치고, 없으면 지운다. 코드·문서와 어긋나면 주석이 틀린 것으로 본다.
- **유지는 기록으로 끝난다.** 남기는 주석(또는 같은 사유를 공유하는 묶음)마다 사유 한 문장을
  그 패스의 `passes/` 유지 목록에 적는다. 사유를 적지 않은 유지는 판정 완료가 아니다.

### 운영 규칙 — 포인터는 남기고, 포인터가 가리키는 내용의 사본은 지운다

가장 자주 마주치는 형태는 「출처를 밝히면서 그 내용을 함께 옮겨 적은」 주석이다.

```go
// The state machine (see docs/prd/lifecycle.md, docs/prd/state-api.md):
//
//	active  ──idle 60m──▶ idle ──idle 60m total──▶ snapshot
```

**주석이 스스로 출처를 밝히고 있다는 것은 그 내용이 복원 가능하다는 자백이다.** 이때
`see docs/...`라는 **경로(포인터)는 남기고**, 그 뒤에 옮겨 적은 **사본은 지운다.** 포인터는
재진술이 아니라 SSOT로 가는 길이고, 사본은 원본이 고쳐질 때 어긋나는 쪽이다.

### 운영 규칙 — 원장은 표 하나다, 손으로 쓴 합계는 없다

- **원장에는 표와 「읽는 법」만 둔다.** 경위·병합 재측정 기록은 해당 패스의 `passes/` 파일이나
  PR 본문으로 간다.
- **합계·잔량을 원장에 저장하지 않는다.** 판정 완료 줄·행 수, 축별 미판정 수, 미등재 여부는
  게이트가 표와 실측에서 계산해 출력한다. 손으로 쓴 집계 값은 언제든 낡는다.
- **판정하지 않은 주석을 들이는 PR**(자매 모델의 기능 PR 등)은 공유 값을 올리지 않고 **자기
  파일의 행을 더하거나 고치고 판정 칸을 `—`로** 둔다. 이미 판정된 행의 파일에 주석을 더하면
  그 행의 줄 수·지문을 갱신하고 판정 칸을 `—`로 되돌린다(증분만 판정했으면 그 결과를 적는다).
- **행 순서**는 범위의 첫 파일 경로의 사전순이다. 새 행을 표 끝에 덧붙이지 않는다 — 두 PR이
  같은 자리에 덧붙이면 충돌한다. 행은 순번이 아니라 **범위(첫 파일 경로)로 가리킨다.**
- **줄 번호는 쓰지 않는다.** 다음 판정이 그 파일에서 주석을 지우면 좌표가 밀려 조용히 썩는데
  지문과 달리 줄 번호는 어떤 규칙도 재측정하지 않는다. 게이트의 R6이 그것을 금지한다.

### 충돌 시 기본 방향

코드·문서·이력이 SSOT다. 주석이 그것들과 어긋나면 **주석이 틀린 것으로 본다.**

- 필요 사유를 댈 수 있으면 → 남긴다(사유를 적어 둔다).
- 필요 사유를 댈 수 없으면 → 지운다.
- 사유가 없어서 지워야 하는데 **원본의 부실**이면 → 주석을 남기는 대신 **원본(문서·이름·커밋
  메시지)을 고친다.**
- **모호하면 지운다.** 필요성 시험에서 사유를 못 대면 그것이 판정의 끝이다. 판단이 갈리는
  주석은 보존하고 **갈렸다는 사실**을 [판정 원장](./ledger.md)에 남긴다.

## 판정 절차

1. 판정 범위를 **파일 단위로** 정한다(레포 전체 − 제외). 한 번에 전 범위를 훑지 않는다 —
   초기 격차가 크다는 것은 알려진 사실이고, 한 번에 좁힐 대상이 아니다.
2. 범위 안의 주석을 **한 줄도 빠짐없이** 읽는다. 「흔한 중복 유형 목록」에서 찾지 않는다 —
   그런 목록은 가설이지 판정이 아니다.
3. 제거하는 줄마다 **좌표**를 적는다: 어느 파일의 어느 **심볼**이, 또는 어느 문서의 어느 AC가
   이미 이 내용을 말하는가. 좌표 없이 「중복이다」고만 적으면 리뷰가 불가능하다.
4. 유지 판정도 판정이다. 남기는 주석마다 **필요 사유 한 문장**을 `passes/` 유지 목록에 적는다.
5. 판정한 줄 수(제거 + 유지)와 **판정 칸**(`완료`/`—`)을 [판정 원장](./ledger.md)에 기록한다.
   **성과는 지운 줄 수가 아니라 판정된 줄 수다.**

## 판정 기록

판정한 범위와 그 범위의 현재 줄 수·지문은 **[판정 원장](./ledger.md)** 에 있고, 패스별 제거
근거표와 유지 목록은 **[`passes/`](./passes/)** 에 패스 하나당 파일 하나로 있다. 원장 행의 결과
칸이 그 상세를 링크한다. 게이트가 파싱하는 마커는 `ledger.md`에만 있다.

## 범위 밖

판정 대상 범위는 **포함 목록이 아니라 「레포 전체에서 제외를 뺀 것」**이다 — 새 디렉터리는 등록
없이 자동으로 범위에 든다. 제외는 다음 세 부류뿐이다.

| 부류 | 왜 빼는가 | 이 레포에서 |
|---|---|---|
| ① 문서 | 저장소 문서는 코드 사이의 주석이 아니라 별도 매체다. 정책 디렉터리도 여기 있어, 대상에 넣으면 정책이 자기 자신을 심사한다 | `docs/` · 모든 `*.md` |
| ② 편집 불가 | 지워도 재생성·재설치되어 판정할 의미가 없다 | 벤더·의존성·빌드 산출물·락 파일, 머리 5줄에 `DO NOT EDIT`·`@generated` 표식이 있는 파일 |
| ③ 주석 문법 없음 | 주석이라는 개념이 없어 패턴이 무엇을 잡든 오탐이다 | JSON·CSV·TXT 등 데이터 파일, 바이너리 |

**레포 고유 제외**는 아래 `comment-scope-exclude` 블록에 한 줄에 ERE 하나로 적는다. 줄마다 어느
부류(①②③)인지를 블록 바로 위 산문에 적는다 — 부류를 댈 수 없는 제외는 둘 수 없다.

```comment-scope-exclude
```

**현재 이 블록은 비어 있다** — 이 레포에 추가할 레포 고유 제외가 아직 없다. 블록이 비면
고정부만 적용한다. (미분류 파일 `scripts/e2e/pocket-aide.Dockerfile` 은 제외가 아니라 **언어군
표의 빈틈**이다 — 파일 이름이 `Dockerfile*` 패턴에 걸리지 않는다. 제외로 덮으면 주석이 사각지대에
묻히므로, 고쳐야 할 곳은 템플릿의 언어군 표다.)

- **문서·커밋 메시지 자체의 품질** — 다만 「주석을 지우려면 원본을 고쳐야 한다」는 판정이
  그 원본을 고치는 작업을 낳을 수 있고, 그건 정상이다.
- **주석의 정확성**(코드와 맞는가) — 이 정책은 필요성만 본다. 다만 필요 사유가 서지 않는 주석이
  낡아 틀려 있으면 그것은 제거 근거를 강화한다.

## 지문 사각지대

모델 as-is 지문은 **세 표면**의 합이다. 게이트는 지금 **L(줄머리 주석)** 표면만 재측정한다.

| 표면 | 무엇 | 추출 | 게이트가 재측정하는가 |
|---|---|---|---|
| **L** 줄머리 주석 | 언어군 패턴에 걸리는 줄 | `grep` | 예 |
| **D** docstring 본문 | Python 모듈·클래스·함수 docstring | `ast` | 아니요 |
| **E** 줄 끝·줄 중간 주석 | 코드 **뒤에** 오는 주석 | `tokenize` · 줄 스캐너 | 아니요 |

- **L이 원장이 세는 표면이다.** 첫 진단 줄 `lines=… files=… unclassified=…`도 L만 센다.
- **E를 보지 않는 파일**: MIXED·MARKUP 언어군, 그리고 줄 중간 `#`이 주석이 아닌 HASH 파일
  (Dockerfile류·`.gitignore`류·`.env`·ini/cfg류).
- **기계가 읽는 주석은 D·E에서도 뺀다.** D는 지시자가 **줄머리**에 오는 docstring 줄만 뺀다 —
  문장 중간의 지시자 낱말은 그대로 센다. 지시자 **뒤에 붙은 사유**는 사람의 문장이므로 E로 남긴다.
- 알려진 사각지대: MIXED·MARKUP 파일과 줄 중간 `#`이 주석이 아닌 HASH 파일의 줄 끝 주석,
  `*`로 시작하지 않는 블록 주석 연속 줄, Python 밖의 docstring 성격 문자열, 줄 스캐너의 문자열
  추적 한계(JS 정규식 리터럴, JSX 텍스트의 따옴표·`//`, Rust 수명 표기). 오탐·누락 모두 결정적이다.
