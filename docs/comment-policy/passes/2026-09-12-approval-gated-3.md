| `f3MarkerBudget` doc (2줄) | 60초가 **예산이 아니라 취소선**이라는 것 | 매핑 행은 「60초 도구 예산」이라고만 적는다. 넘기면 **CLI 가 호출을 취소한다**(기다려 주지 않는다)는 반의미는 레포 어디에도 없고, 그것을 모르면 다음 편집이 대기 예산을 늘려 「더 안전하게」 만들었다고 생각하면서 실은 취소된 호출을 기다리게 된다. CLI 문서에도 없는 관측이라 **애매하면 남긴다**를 적용했다 |
| `gatewayStatus` doc (2줄) | 부재를 실패가 아니라 `""` 로 답하는 이유 | `return ""` 은 보이지만 그것이 **계약**이라는 것은 안 보인다. 「없으면 실패시키자」로 바꾸면 헬퍼가 CLI 와 경쟁해 간헐 실패가 되고, 그때 실패 메시지는 게이트웨이를 가리켜 원인을 숨긴다. 「아직 없음」과 「결정됨」이 다른 답이라는 것은 대역 헤더도 매핑 행도 적지 않는다 |
| 대역 정책 설정 옆 (2줄) | 대역이 **싱글턴**이고 `defaultStatus` 가 그 위의 가변 전역이라는 것 | 대역 헤더는 「It starts as PENDING」이라고 **초기값**만 적는다. 한 인스턴스를 클러스터의 모든 테스트가 공유하므로 앞선 테스트가 approve-all 로 바꿔 놓았을 수 있다는 것 — 그래서 이 한 줄이 땜질이 아니라 격리 장치라는 것 — 은 어디에도 없다. 지우면 이 테스트는 **다른 테스트가 먼저 돌 때만** 조용히 거짓 통과한다 |
| 스트림 개설 순서 (2줄) | 스트림이 write **앞에** 붙어야 한다는 순서 계약 | `s6Open` → `writeShell` 순서는 보이지만 그것이 계약이라는 것은 안 보인다. 뒤집으면 놓치는 바이트가 **하필 아래에서 대조하는 그 바이트**라, 단언은 초록인 채로 아무것도 사지 않게 된다. 14차가 프로브 부착 순서에서 남긴 것과 같은 성질이다 |
| `f3EventuallyMarker` doc (2줄) | 공유 `eventuallyShellRead` 보다 예산이 긴 이유 | 90초는 그 자체로 마법의 수다. 이 대기가 셸 출력이 아니라 **CLI 기동 + MCP 왕복 + 게이트웨이 폴링**을 기다린다는 구성은 코드 형태에 없고, 모르면 다음 사람이 「하네스 값에 맞추자」로 줄여 간헐 실패를 만든다 |
| `f3DrainUntil` doc (2줄) | 마커까지만 읽는 이유 — 세션은 도구 결과 뒤에도 계속 바이트를 낸다 | 「끝까지 드레인」이 더 자연스러운 형태이고, 그렇게 바꾸면 이 루프는 **영원히 돌아 테스트가 타임아웃으로 죽는다**. 스트림의 수명이 단언의 수명보다 길면 안 된다는 계약은 코드에도 매핑 행에도 없다 |

## 판단이 갈린 것

- **`f3MarkerBudget` 의 60초를 남길지.** 매핑 행이 그 숫자를 「CLI 의 60초 도구 예산」으로 이미
  적으므로 숫자만 놓고 보면 ② 로 복원된다. 남긴 것은 숫자가 아니라 **그 시각에 일어나는 일**
  (취소)이다. 두 줄로 줄여 「천장 아래로 잡았다」는 복원 가능한 절반은 걷고 반의미만 남겼다.
- **절 배너 7줄을 전부 걷었다.** 읽기 편의를 잃는다는 반론이 있었고, 실제로 이 파일은 테스트 하나가
  130줄을 넘는다. 그래도 걷은 이유: 배너 문구가 매핑 행의 **갈래 이름과 글자까지 같아** 전형적인
  사본이고, 각 절이 `t.Fatalf` 로 자기가 무엇을 사는지 이미 문장으로 말한다. 「판정된 줄 수가 성과」
  라는 절차 규칙과 「사본은 지운다」가 여기서는 같은 방향을 가리켰다.
- **`operator` doc 을 통째로 걷은 것.** ⓑ(ClusterIP 라 테스트 프로세스에서 몰 수 없다)는 k8s 일반
  지식과 매니페스트 형태로 복원되지만, 「**하필 세션 MCP 컨테이너**에서 몬다」는 선택이 AC-F2 의
  네트워크 정책과 맞물린다는 점에서 한 번 더 저울질했다. 걷은 쪽으로 간 것은 본문이
  `helperPodsFor` → `f4Sh(…, sessionMCPContainer, …)` 로 그 선택을 **실행으로** 적고 있어 ① 로
  닿기 때문이다. 이 판단이 뒤집히면 되살릴 자리는 이 표다.

**코드 동작은 변하지 않았다.** 주석 줄을 걷어낸 뒤의 대조로 확인했다 — 비-주석·비-공백 줄이
판정 전후 **204줄로 같고**, 공백을 정규화하면 바이트 동일이다. 유일한 차이는 `f3Prompt` 의 정렬
공백 한 곳으로, 주석이 갈라 두던 `const` 블록이 합쳐지며 `gofmt` 가 다시 맞춘 것이다.
