- **🆕 Codex의 설정 밖 도구 (AC-J5)**: Codex 0.166.0의 원격 모델 카탈로그가 코드 모드(`apply_patch` 포함)와 하위 에이전트 도구를 강제해, 이 둘은 관리형 설정으로 끌 수 없다. 파일 쓰기는 읽기 전용 샌드박스·`approval_policy=never`·러너 킬 스위치가 막고 이미지 빌드 검사가 셸·이미지 도구의 재등장을 막지만, 「모델에 보이는 도구」 수준에서는 사용자 결정(대화·스킬·K3s MCP만)과 완전히 같지 않다.
- **🆕 풀 슬롯의 토큰이 세션 컨테이너에 있다 (AC-N5 ↔ AC-E7·AC-M2)**: 사용자 결정(2026-11-07)으로 구독 계정의 로그인 파일을 프록시로 숨기지 않고 셸이 있는 주 컨테이너에 둔다. 그 세션의 에이전트(또는 그것을 조종한 프롬프트)가 슬롯 계정의 refresh token을 읽어 밖으로 낼 수 있다. 독점 임대는 두 파드의 동시 갱신만 막지 유출은 막지 않는다. 숨기려면 슬롯 파드가 혼자 갱신하고 세션은 공급자 호출을 그 파드로 보내는 구조가 필요한데, Codex·Claude Code가 커스텀 base URL로 구독 백엔드를 부를 수 있는지는 실측하지 않았다.
- **🆕 슬롯 PVC와 동적 프로비저너의 이름 규칙 (AC-N1)**: 운영의 `efs` 클래스는 PVC 이름으로 경로·access point를 정한다(`/${.PVC.name}`, `reuseAccessPoint`). 슬롯 PVC 이름에 네임스페이스를 넣어 프리뷰 슬롯이 운영 슬롯과 갈리게 했지만, 같은 네임스페이스 이름을 다시 쓰는 환경(프리뷰 번호 재사용 등)은 이전 환경의 로그인을 물려받는다. kind의 local-path에서는 슬롯을 받은 세션이 그 노드에 묶인다.
